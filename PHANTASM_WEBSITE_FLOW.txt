OVERVIEW — WHAT THE WEBSITE IS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PHANTASM is a single-page React application (SPA) served on localhost:3000.
It is a real-time SOC (Security Operations Centre) dashboard — not a
multi-page website. There is no public marketing site, no login page,
no navigation menu. The entire product is one full-viewport screen that
comes alive when a session starts.

TOTAL SCREENS: 4 states of the same single page
  State 1 — IDLE        (system running, no active session)
  State 2 — ACTIVE      (session live, attacker inside ShadowMesh)
  State 3 — DOSSIER     (session ended, dossier generating/ready)
  State 4 — HISTORY     (side drawer showing past sessions)

The page never navigates away. State transitions are animated in-place.

USER ACTION FROM IDLE:
  User does nothing — the dashboard waits for the first packet to hit
  ShadowMesh. When it does, the system auto-transitions to ACTIVE state.
  The [▶ START SESSION] button manually triggers session start for demo
  purposes (sends a test packet to kickstart the state machine).

ANIMATION SEQUENCE (orchestrated, total ~2 seconds):

T+0ms:
  Header status chip: grey → green. Text: "SESSION ACTIVE"
  Green dot begins its pulsing animation (1.5s cycle)

T+100ms:
  Session timer begins counting up from 00:00:00

T+200ms:
  Left panel border: gains amber accent glow (1px amber border animates in)
  Right panel border: same

T+300ms:
  Graph panel: opacity 40% → 100% (all nodes brighten), duration 400ms

T+400ms:
  Graph overlay text fades out (opacity 1 → 0, 300ms)
  New overlay text appears briefly: "SHADOWMESH ACTIVE — MONITORING"
  (amber, centre, fades in 300ms, holds 1s, fades out 500ms)

T+600ms:
  Graph nodes begin their idle breathing animation — very subtle scale
  pulse (1.0 → 1.05 → 1.0, 3s cycle, staggered per node so they don't
  all pulse simultaneously)

T+1000ms:
  Session stats in right panel reset to zero and begin counting
  Stress chart initialises with a flat baseline

T+2000ms:
  System fully active. All transitions complete.
  Dashboard is in ACTIVE state.

REAL-TIME BEHAVIOURS DURING ACTIVE STATE:

EVERY COMMAND RECEIVED:
  1. New entry slides into bottom of command feed (translateY 8px → 0)
  2. Command feed auto-scrolls to show newest entry
  3. ATT&CK badge appears with colour matching tactic
  4. Target host node in graph: transitions to probed state (amber pulse)
  5. Stress chart: new data point added, line redraws
  6. Header command counter increments with subtle number animation

EVERY 5 COMMANDS (PROFILE UPDATE):
  1. MirrorTrap publishes profile update via WebSocket
  2. Expertise gauge needle sweeps to new position (600ms animation)
  3. Objective bars animate to new percentages (400ms)
  4. Session stats update (commands, techniques, dwell time)
  5. Right panel briefly highlights (amber border glow flash, 300ms)

WHEN HOST IS ACCESSED (authenticated connection):
  1. Node colour transitions: amber (probed) → red (accessed)
  2. Red glow appears on node
  3. ⚠ icon overlays the node
  4. An edge from the attacker's entry point to this host animates in
     (dashed amber marching ants showing the lateral movement path)
  5. "Assets Accessed" counter in bottom bar increments

WHEN STRESS EVENT DETECTED (ICI acceleration):
  1. State indicator in right panel transitions to STRESSED
  2. Amber ⚡ icon pulses briefly
  3. Stress chart: the line dips sharply (lower ICI = more stress on chart)
  4. Red zone shading appears on stress chart below the baseline
  5. Small callout box appears: "Stress onset detected — cadence +340%"

WHEN HIGH ATTRIBUTION DETECTED (>60% APT overlap):
  1. Attribution radar in right panel: data polygon turns red
  2. Section border turns red with pulsing glow
  3. Header briefly shows ⚠ amber chip: "HIGH ATTRIBUTION — APT-36"
  4. Chip auto-dismisses after 5 seconds

WHEN ADAPTIVE TRIGGER FIRES (crown jewel materialisation):
  FULL SEQUENCE (described in UI/UX doc Section 4.6):
  1. Amber glow appears at new node position
  2. Node materialises with spring scale animation
  3. Outer ripple ring fires
  4. Node label slides in
  5. New edges draw connecting to subnet
  6. "CROWN JEWEL MATERIALIZED" text briefly overlays graph
  7. Right panel profile section pulses amber

WHEN C2 CALLBACK DETECTED:
  1. Bottom bar IOC counter increments with red flash
  2. New entry in command feed tagged [T1041 EXFIL] with deep red background
  3. Small red banner briefly appears at top of graph:
     "C2 CALLBACK DETECTED — 45.xxx.xxx.12:443"
     (slides down from top edge, holds 4 seconds, slides back up)

USER INTERACTIONS IN ACTIVE STATE:

  HOVER OVER GRAPH NODE:
    Tooltip appears showing: hostname, IP, OS, open ports, status, last probed
    Other nodes dim to 50% opacity (focus on hovered node)
    Connected edges highlight

  CLICK GRAPH NODE:
    Node detail drawer slides in from right edge of graph panel (240px wide)
    Drawer content:
      - Full hostname (large, amber)
      - IP address (mono)
      - Declared OS and version
      - All emulated services with ports
      - Interaction log: list of attacker commands targeting this host
      - Current status badge
    Close: click X in drawer or click outside

  CLICK ATT&CK BADGE IN COMMAND FEED:
    Small tooltip appears showing:
      - Full technique name
      - Tactic category
      - One-line description of what this technique means
      - Confidence score
    Auto-dismisses after 4 seconds

  CLICK [■ END SESSION] BUTTON:
    Confirmation micro-modal appears (does not block dashboard):
      Small card (240px) sliding down from header:
        "End session and generate dossier?"
        [Confirm] [Cancel]
      If Confirm: transition to DOSSIER state
      If Cancel: modal slides back up, session continues

  DEMO CONTROLS (bottom-left of graph, small buttons):
    [Force APT Trigger]    — manually fires crown jewel materialisation
    [Force Stress Event]   — manually triggers stress state in profile
    [End Session]          — immediately ends session, triggers dossier
    These are failsafes for demo. Styled as small, unobtrusive text links.

ANIMATION SEQUENCE:

T+0ms:
  Header status chip: "SESSION ACTIVE" → "SESSION ENDED"
  Chip colour: green → amber
  Session timer freezes at final time

T+200ms:
  All probed/accessed nodes in graph: pulse animation stops
  Nodes hold their final colour (probed = amber, accessed = red)
  Graph force simulation freezes — network becomes a static record
  Graph opacity dims slightly to 70% — it is now history, not live

T+400ms:
  Left panel command feed: scroll stops, newest commands visible
  A thin amber line appears at the bottom of the feed: "SESSION ENDED"
  timestamp + total command count

T+500ms:
  Right panel: "GENERATING DOSSIER..." spinner appears below session stats
  [⬇ GENERATE DOSSIER] button: shows spinning icon + "GENERATING..."

T+500ms–60000ms:
  Progress indicator in dossier button:
  A subtle progress bar fills the button background from left to right
  over the estimated 60-second generation window
  Text shows: "GENERATING... 0%" → "GENERATING... 45%" → etc.
  Progress is estimated (not real — LLM generation doesn't report %)
  But the visual is reassuring and keeps judges engaged

T+generation_complete:
  Dossier notification slides in from bottom-right (see UI/UX spec 4.4)
  [⬇ GENERATE DOSSIER] button: turns green, text "DOSSIER READY"
  Notification shows: session summary + [VIEW PDF] button

CONNECTION SUCCESS:
  WebSocket handshake completes.
  Client sends: { type: "subscribe", client: "dashboard" }
  Server responds: { type: "system_status", shadowmesh: "online",
                     mirrortrap: "ready", redis: "connected" }
  Dashboard renders system status dots in footer.
  Dashboard moves to IDLE state.

EVENT FLOW DURING SESSION:

  SERVER → CLIENT events (server pushes, client just renders):
    "session_start"     → transition to ACTIVE state
    "command"           → new command feed entry
    "profile_update"    → update all profile card components
    "topology_update"   → add node(s) to graph, trigger animations
    "ioc_detected"      → update IOC counters
    "stress_event"      → update state indicator
    "attribution_alert" → show high attribution warning
    "c2_callback"       → show C2 banner, update counters
    "session_end"       → freeze dashboard, show dossier progress
    "dossier_ready"     → show notification, enable download

  CLIENT → SERVER events (user actions):
    "session_start_manual"     → [▶ Start Session] clicked
    "session_end_manual"       → [■ End Session] confirmed
    "dossier_generate_manual"  → [⬇ Generate Dossier] clicked
    "force_trigger_apt"        → demo control button clicked
    "force_trigger_ransomware" → demo control button clicked

DISCONNECTION HANDLING:
  Small "RECONNECTING..." chip appears in header centre (non-blocking)
  Retry: 1s, 2s, 4s, 8s intervals (capped at 8s)
  Dashboard data preserved during disconnect (no state loss)
  On reconnect: server sends current session state to re-sync client
  After 60s no reconnect: "CONNECTION LOST" chip, manual reconnect button

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ERROR: SHADOWMESH OFFLINE
  Graph panel shows: "⚠ SHADOWMESH OFFLINE" overlay (amber text, centre)
  System status dot: ShadowMesh → red
  [▶ Start Session] button: disabled, tooltip "ShadowMesh not responding"

ERROR: MIRRORTRAP MODEL NOT LOADED
  Profile card shows: "MODEL NOT LOADED" in all sections
  Commands still appear in feed but with no ATT&CK tags
  System status dot: MirrorTrap → red

ERROR: REDIS DISCONNECTED
  No real-time updates flow.
  "REDIS DISCONNECTED" chip in header.
  Dashboard freezes but does not crash.
  System status dot: Redis → red

ERROR: DOSSIER GENERATION FAILED
  After 65 seconds: if no dossier_ready event received:
    Button shows: "⚠ GENERATION FAILED — RETRY"
    Click retry: triggers cached fallback dossier (pre-generated for demo)
    Cached dossier downloads immediately — no failure visible to judge.
    This is the critical failsafe from the PRD.

ERROR: GRAPH RENDER FAILURE
  If D3 crashes (rare):
    Graph panel shows fallback: a static SVG diagram of the topology
    (pre-rendered, not interactive but visually correct)
    This was pre-built and exists as a fallback component.

EMPTY COMMAND FEED (session started but no commands arriving):
  After 30s with no commands: gentle prompt in feed:
    "Awaiting first probe... ShadowMesh listening."
  This handles the case where the attacker terminal hasn't started yet.

  Returns: { shadowmesh, mirrortrap, redis, uptime }
  Used by: System status dots (polled every 10s)

  Returns: { nodes: [...], edges: [...] }
  Used by: Initial graph render on page load

GET  /api/sessions
  Returns: [ { id, start, end, expertise, objective, commands, dwell } ]
  Used by: History drawer

GET  /api/sessions/{session_id}
  Returns: Full session record JSON
  Used by: Historical dossier view

GET  /api/dossier/{session_id}
  Returns: { summary, narrative, techniques, iocs, attribution }
  Used by: Dossier preview panel

GET  /api/dossier/{session_id}/pdf
  Returns: PDF file stream (application/pdf)
  Used by: [DOWNLOAD PDF] button

POST /api/session/start
  Body: {}
  Returns: { session_id, started_at }
  Used by: [▶ Start Session] button

POST /api/session/end
  Body: { session_id }
  Returns: { ended_at, duration, summary }
  Used by: [■ End Session] confirm

POST /api/dossier/generate
  Body: { session_id }
  Returns: { status: "generating" }
  Used by: [⬇ Generate Dossier] button (auto-called on session end too)

POST /api/demo/trigger
  Body: { trigger: "apt_crown_jewel" | "ransomware" | "stress_event" }
  Returns: { status: "triggered" }
  Used by: Demo control buttons (failsafe)

WS   /ws
  Persistent WebSocket connection for all real-time events.

REACT STATE MANAGEMENT STRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Use Zustand (lightweight, no boilerplate) for global state.

STORE STRUCTURE (sessionStore.js):

  {
    // System
    systemStatus: { shadowmesh, mirrortrap, redis },
    wsConnected: boolean,

    // Session lifecycle
    sessionState: "idle" | "active" | "ended",
    sessionId: string | null,
    sessionStartTime: Date | null,
    sessionEndTime: Date | null,

    // Command feed
    commands: [{ id, timestamp, text, techniques, severity, ici_ms }],
    commandCount: number,

    // Operator profile
    profile: {
      expertise: { level, confidence },
      objective: { type, scores },
      state: { type, onset_seconds },
      attribution: [{ group, score }]
    },

    // Graph topology
    nodes: [{ id, hostname, ip, role, status }],
    edges: [{ source, target, active }],

    // Session stats
    stats: {
      commands: number,
      techniques: number,
      dwell: number,
      engagementScore: number
    },

    // IOCs
    iocs: { c2_ips: [], payloads: [], domains: [] },

    // Stress chart
    iciHistory: [{ time, ici_ms }],

    // Dossier
    dossierStatus: "idle" | "generating" | "ready" | "error",
    dossierData: object | null,

    // Actions
    addCommand: (command) => void,
    updateProfile: (profile) => void,
    addNode: (node, edges) => void,
    setSessionState: (state) => void,
    setDossierReady: (data) => void,
    resetSession: () => void
  }

COMPONENT SUBSCRIPTIONS (each component subscribes to only what it needs):
  Header:         sessionState, sessionStartTime, stats, wsConnected
  CommandFeed:    commands (slice — latest 200 only for performance)
  NetworkGraph:   nodes, edges (managed by D3, not React state)
  ExpertiseGauge: profile.expertise
  ObjectiveBars:  profile.objective
  StateIndicator: profile.state
  AttributionRadar: profile.attribution
  SessionStats:   stats
  StressChart:    iciHistory (slice — latest 100 points)
  BottomBar:      iocs, iciHistory
  DossierPanel:   dossierStatus, dossierData
