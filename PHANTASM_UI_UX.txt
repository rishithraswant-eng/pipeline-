SECTION 1: DESIGN PHILOSOPHY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PHANTASM's dashboard is not a utility interface. It is a command centre.
It must communicate power, intelligence, and precision at a glance — because
the 90 seconds a judge spends looking at it must leave a permanent impression.

Three words define the design language: CINEMATIC. SURGICAL. ALIVE.

CINEMATIC — The dashboard looks like something from a high-budget cyber
thriller. Dark background, amber light sources, data that breathes and moves.
Not garish — restrained. Every animation serves information, not decoration.

SURGICAL — Nothing is on screen that doesn't need to be. Every pixel earns
its place. Information density is high but never cluttered. A trained eye
can absorb the entire dashboard state in under 3 seconds.

ALIVE — The dashboard is never static. The network graph pulses. The command
feed scrolls. The profile card updates. The stress chart draws itself in
real-time. A static screenshot of this dashboard looks incomplete — because
it is meant to be seen in motion.

The visual inspiration is the intersection of:
  - Bloomberg Terminal (information density, professional credibility)
  - Nmap Zenmap (network topology as primary visual)
  - Modern SOC dashboards (Splunk SIEM, Darktrace Antigena)
  - Cinematic UI design (Ex Machina, Tron: Legacy interfaces)

Avoid: gradients everywhere, neon overload, rounded-everything softness.
This system deals with nation-state threats. It should look like it knows that.

3.4 CENTRE PANEL — NETWORK GRAPH
──────────────────────────────────

This is the visual centrepiece of the dashboard. It must be stunning.

Border: none — seamless with header and bottom bar
Padding: 24px

GRAPH IMPLEMENTATION (D3.js v7 Force-Directed):

NODE TYPES AND VISUAL TREATMENT:

  Standard Host Node:
  - Circle, radius: 20px
  - Fill: var(--node-default) = #1E2030
  - Stroke: 1.5px, var(--bg-border)
  - Label: hostname below node, Inter 400, 10px, var(--text-muted)
  - Label truncated to 20 chars if longer

  Probed Host Node (active):
  - Fill: var(--node-probed) = #F59E0B
  - Stroke: 2px, var(--amber-pulse)
  - Drop shadow: var(--glow-node)
  - PULSE ANIMATION:
    @keyframes nodePulse {
      0%, 100% { r: 20; opacity: 1; }
      50% { r: 26; opacity: 0.6; }
    }
    Duration: 1.5s, ease-in-out, infinite
  - Secondary pulse ring: a circle growing from 20px to 50px radius,
    opacity 0.4 → 0, duration 2s, infinite — creates ripple effect

  Accessed Host Node:
  - Fill: var(--node-accessed) = #EF4444
  - Stroke: 2px, #DC2626
  - Drop shadow: var(--glow-red)
  - Small ⚠ icon overlaid at top-right of node

  Crown Jewel Node (materialised by feedback loop):
  - Fill: var(--node-crown) = #FCD34D
  - Stroke: 2px, var(--amber-glow)
  - MATERIALISATION ANIMATION:
    @keyframes materialise {
      0% { r: 0; opacity: 0; filter: blur(4px); }
      60% { r: 24; opacity: 0.8; filter: blur(0px); }
      80% { r: 18; opacity: 1; }
      100% { r: 20; opacity: 1; }
    }
    Duration: 800ms, ease-spring
  - Before appearing: a slow amber glow pulse at the node position for 1s,
    then the materialise animation fires — creates "emergence from nothing"
  - After appearing: continuous gentle amber glow (not full pulse)
  - Small ★ icon overlaid at top-right — marks as crown jewel
  - Label: amber colour, semibold, slightly larger (12px)

  Domain Controller Node:
  - Larger radius: 28px
  - Fill: #1A1228 (deep purple-dark)
  - Stroke: 2px, var(--node-dc)
  - Icon: small "AD" text inside node circle

EDGE (LINK) VISUAL TREATMENT:

  Default Edge:
  - Stroke: var(--node-edge) = #252840
  - Stroke-width: 1px
  - Opacity: 0.6

  Active Lateral Movement Edge:
  - Stroke: var(--amber-glow)
  - Stroke-width: 2px
  - Stroke-dasharray: 6, 3
  - ANIMATION: stroke-dashoffset animates to create "marching ants" effect
    showing directionality of lateral movement
    @keyframes marchingAnts {
      to { stroke-dashoffset: -18; }
    }
    Duration: 800ms, linear, infinite

GRAPH BACKGROUND TREATMENT:
  - Subtle hex grid pattern in SVG (very low opacity — 0.03 — just enough
    to add depth without cluttering)
  - Very faint radial gradient: slightly lighter at centre (#0C0D14 at 0%)
    to void black at edges (#050508 at 100%)

FORCE SIMULATION PARAMETERS:

4.6 CROWN JEWEL MATERIALISATION SEQUENCE
──────────────────────────────────────────

This is THE visual climax of the demo. It must be perfect.

TRIGGER: Feedback controller fires APT-grade mutation directive.

SEQUENCE:
  T+0ms:    Soft amber glow appears at target position in graph
             (a 6px circle, amber, 30% opacity, slowly pulsing)
  T+500ms:  Glow intensifies, radius grows to 40px over 300ms
  T+800ms:  Node materialises:
             - Scale animation: 0 → 1.2 → 1.0 (--ease-spring, 600ms)
             - Blur filter: blur(4px) → blur(0) concurrent with scale
             - Opacity: 0 → 1
  T+800ms:  Outer pulse ring fires (circle expanding 20px → 80px, opacity
             0.6 → 0, duration 1s — single fire, not looping)
  T+1400ms: Node label slides in from below (translateY(8px) → 0, 200ms)
  T+1600ms: New edge connecting to parent subnet animates in
             (stroke-dasharray trick: line draws from source to new node)
  T+2000ms: "CROWN JEWEL MATERIALIZED" text appears briefly in graph
             (amber, centre-top, fades in/out over 2s)
  T+2000ms: Right panel profile section pulses amber briefly
             indicating profile-triggered this mutation

The entire sequence takes ~2 seconds and is unmissably dramatic.

5.1 WEBSOCKET DATA CONTRACT
─────────────────────────────

The frontend subscribes to these event types from the API server:

EVENT: "command"
  Payload: { id, timestamp, text, techniques: [{id, tactic, confidence}],
             severity, ici_ms }
  Action: Prepend to command feed with entrance animation.
          Update stress chart with new ICI data point.

EVENT: "profile_update"
  Payload: { expertise: {level, confidence}, objective: {type, scores},
             state: {type, onset_seconds}, attribution: [{group, score}],
             stats: {commands, techniques, dwell, engagement} }
  Action: Animate all profile card components to new values.
          Update header engagement score and command count.

EVENT: "topology_update"
  Payload: { action: "add_node", node: {id, hostname, ip, role, services},
             edges: [{source, target}], trigger: "apt_crown_jewel" }
  Action: Execute crown jewel materialisation sequence.
          Add node and edges to D3 simulation.

EVENT: "ioc_detected"
  Payload: { type: "c2_ip"|"payload"|"domain", value, timestamp }
  Action: Update IOC counters in bottom bar.
          Brief red flash on bottom bar IOC section.

EVENT: "session_end"
  Payload: { reason: "disconnect"|"timeout"|"manual", duration, summary }
  Action: Stop session timer. Trigger dossier generation animation.

EVENT: "dossier_ready"
  Payload: { path, session_id, generation_time_ms }
  Action: Show dossier notification. Enable download button.

5.2 WEBSOCKET RECONNECTION BEHAVIOUR
──────────────────────────────────────

If WebSocket disconnects:
  - Show a subtle "RECONNECTING..." chip in header (no disruptive modal)
  - Attempt reconnection every 1s for first 5 attempts
  - Every 3s for next 10 attempts
  - After 15 failed attempts: show "CONNECTION LOST" chip, stop retrying
  - All data already received remains visible — no data loss on disconnect

6.2 D3 + REACT INTEGRATION PATTERN
─────────────────────────────────────

Do NOT use React state to manage D3. Let D3 own the DOM inside the SVG.
Use a useRef to hold the SVG element. Use useEffect to initialise the
D3 simulation. Pass new data to D3 via a ref-based update function, not
by re-rendering React. This is the only way to achieve 60fps updates.

  // NetworkGraph.jsx — correct pattern
  const svgRef = useRef(null);
  const simulationRef = useRef(null);

  useEffect(() => {
    // Initialise D3 once on mount
    simulationRef.current = d3.forceSimulation()
      .force("link", d3.forceLink().distance(120))
      .force("charge", d3.forceManyBody().strength(-400))
      .force("center", d3.forceCenter(width/2, height/2));

    // Set up SVG elements once
    const svg = d3.select(svgRef.current);
    // ... initial render
  }, []);

  // When new topology data arrives via WebSocket:
  const addNode = useCallback((newNode) => {
    // Directly mutate D3's data and restart simulation
    // Trigger crown jewel animation sequence
    // Do NOT setState here - D3 handles the DOM
  }, []);
